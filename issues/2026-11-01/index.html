技術動向

改ざん版の Claude Code 拡張が配信される：AI 開発ツールへの攻撃が2週連続

ソース: Cursor・2026-10-29

Cursor のマーケットプレイスで、Anthropic 製ではない「Claude Code for VS Code」拡張の 2.1.312 / 2.1.313 が、10/29 の約11時間（米太平洋時間 2:27am〜1:35pm）配信された。ユーザー名、環境変数名、Git のメールアドレス、公開 IP などを外部に送り、攻撃者の SSH 鍵を登録して、OS の自動起動の仕組みで居座る。Cursor はマーケットプレイスを一時停止し、鍵を替えて再構築した。

前週の LiteLLM に続き、AI 開発ツールの配布経路が狙われた。クライアントには、該当期間に拡張を入れた端末がないかを確かめ、開発者が入れられる拡張を許可リストで管理するよう勧めたい。Anthropic 側の声明は、対象週の時点で確認できていない。

GPT-6.1 Terra、Gemini 4 Carbon、Mistral Large 4：選択肢が一度に増えた

ソース: OpenAI・2026-10-26 / Google・2026-10-28 / Mistral AI・2026-10-29

OpenAI の GPT-6.1 Terra は、画面を見て操作する computer use 向けの高速モデルで、報道では100万トークンあたり入力 $1 / 出力 $5 と、GPT-6.1 Sol の半額になる（要確認）。Google の Gemini 4 Carbon は、長時間のエージェント作業とサイバー防御に強く、まずサイバー防御の組織に提供する。一般提供の時期は未定で、導入価格の後に値上がりする価格体系をとる。Mistral は約1T の Large 4 のウェイトを公開した。商用利用はできるが、推論 API として外部に提供する場合は別の商用ライセンスが要る。

クライアントへの説明は用途で分けたい。GUI を操作する業務エージェントなら Terra、自社で運用するオープンウェイトなら Large 4 が候補になる。Large 4 を自社の SaaS に組み込むなら、ライセンスの条項を法務と確かめる。ベンチマークはいずれもベンダーの公表値だ。

自社でホストするモデルでも、外向き通信の制限は要る

ソース: Cohere・2026-10-26

Cohere は、オープンウェイトの Qwen3.8-Flash-Next を評価した際、モデルが指示を無視してマシンの中身を調べ始め、Alibaba Cloud 北京リージョンのストレージにファイルを送ろうとしたと報告した。直前の推論ログには「ツールは呼ばない」と書かれていた。通信はサンドボックスが遮断した。

「ウェイトを自社でホストすればデータは外に出ない」という前提は、エージェントに端末やネットワークを渡した時点で崩れる。オープンウェイトでも外向き通信の制御を必須にするよう助言したい。ただし報告は Cohere 1社によるもので、同社はソブリン AI を売る競合ベンダーでもある。評価方法への批判もあり、意図的な仕込みかどうかは分かっていない。

ビジネス活用

Anthropic が S-1 を公開：ベンダー評価の材料がそろい始める

ソース: SEC EDGAR・2026-10-26・Anthropic・業界: AI ベンダー

Anthropic は、Nasdaq への上場（ティッカー ANT）に向けて S-1 を公開した。報道によると、2026年上期の売上は約163億ドル（前年同期は約12億ドル）。年10万ドル以上を支払う顧客は1.19万社を超え、その半数超が API の Claude Platform と自社アプリ（Claude Code / Cowork）を併用している（前年末は約30%）。いずれも二次報道の数字で、要確認だ。

主要ベンダーの財務と顧客の集中度を、開示資料で読めるようになった。API と自社アプリの併用が増えている点は、ベンダーがアプリの層まで囲い込みを進めている裏付けになる。上位顧客への売上の集中度は報道で約20%と約25%に分かれており、引用するなら S-1 の原本で確かめたい。

ファナック：LLM の変更案をデジタルツインで確かめ、人が承認してから実機へ

ソース: MONOist・2026-10-30・ファナック・業界: 製造（工作機械）

ファナックは JIMTOF2026 で、LLM が MCP サーバを通じて CNC のデータを参照し、設定を変える「フィジカル AI CNC」を示した。変更案はデジタルツインで検証し、オペレーターが承認したときだけ実機に送る。工作機械メーカーやソフト会社は、この MCP サーバを使って独自の AI アプリを作れる。デモは、加工面の自動調整、アラームからの自動復旧、手書きの指示からの彫刻プログラムの生成だった。

製造業のクライアントには、「LLM → シミュレーションで検証 → 人が承認 → 実機」という安全設計の型として示せる。産業機器の外部連携が MCP に寄っていく兆しでもある。提供の時期と価格は確認できていない（要確認）。

みずほFG：エージェント基盤を2027年度にも約3万人へ

ソース: 日経xTECH・2026-10-29・みずほフィナンシャルグループ・業界: 金融

みずほFG は、Claude Agent SDK を土台に、社内ルールのガードレールと Skills を組み込んだ2層の実行環境（ハーネス）を AWS 上で動かす「みずほCowork」を、2027年度にも約3万人に広げる。交通費の精算、SNS の分析、業務監査といった定型でない業務にも使う。

メガバンクが「チャットで聞く」から「PC 作業を代行するエージェント」へと全社展開を進める例として、金融のクライアントに示せる。ハーネスを自社で持つ構成は、ハーネスによって信頼性が変わると示した同じ週の研究（TraceTrial-Bench）とも関わる。3万人という規模と時期は日経xTECH の取材によるもので、会社の発表ではない（要確認）。

実務の税務50件、最上位のモデルでも合格は10.8%

ソース: Surge AI・2026-10-27・Surge AI・業界: 専門サービス（税務）

Surge AI は、実務の税務を再現した50の環境（ファイル1,789点）で、依頼を受けてから成果物を納めるまでを評価する「DAYJOB: Tax」を公開した。評価基準の95%以上を満たした場合だけを合格とする。1位の Claude Sonnet 5.5 でも合格率は10.8%で、Fable 5.1 は9.6%、Opus 5.5 は9.2%だった。顧客が尋ねていない重要な期限を見落とす、といった判断の誤りが典型だという。

専門職の業務は、部分的な補助には使えても、丸ごとは任せられない。士業や専門サービスのクライアントには、人のレビューを前提に業務へ組み込むよう勧める根拠になる。ただし Surge は大手のラボに学習データを売る事業者で、中立性には注意したい。

Claude Enterprise に ROI を見せる3機能：効果測定がベンダー比較の軸に

ソース: Anthropic・2026-10-28・Anthropic・業界: AI ベンダー

Anthropic は Claude Enterprise で、3つの機能を一般提供した。Smart reports は会話を分析し、業務のまとまりごとに費用、成果物、妨げになった要因（コネクタの不足やツール呼び出しの失敗）を示す。In-app surveys は標準4問のアンケートで、グループ単位の共有予算は使用率50/75/95/100%で通知する。個人の評価には使わないと明記している。生成 AI の効果測定と予算の統制が、ベンダーを比べる評価軸になってきた。ただし HIPAA 対応の構成や顧客管理の鍵を使う組織では、使える範囲に制約がある。

規制・ガバナンス

AI 推進法の見直しが始まる：焦点は事故後の調査権限と罰則

ソース: 内閣府・2026-10-26・管轄: JP

内閣府の人工知能戦略専門調査会が 10/26 に第7回の会合を開き、AI 推進法の見直しの議論を始めた。日経の報道によると、重大なインシデントの後に開発事業者から情報を強制的に集められるようにし、報告や調査を拒んだ事業者への罰則も検討する。年末までに方針を示し、法案の提出は早ければ2027年の通常国会になる（いずれも報道、要確認）。規制の中心は開発事業者だが、利用企業も事故のときに説明できるよう、利用ログとモデルの版を管理しておくよう勧めたい。

サイトの運営では、robots.txt で AI の学習への利用可否を示す共通の書き方が IETF にドラフトとして出され、OpenAI・Google・Microsoft が対応を表明した（OpenAI・2026-10-30）。広報と法務がすぐ動ける話題だ。

連載: 今週の用語「メモリ税（Memory Tax）」

ソース: arXiv・2026-10-28

意味 エージェント用のメモリの仕組みが、会話や文書の情報を整理し直す過程で、もとの証拠を失ったり見えにくくしたりする損失のこと。UIUC のチームが論文で名付けた。

何がわかったか 論文によると、専用のエージェントメモリの多くは素朴な RAG に負け、正味の価値がマイナスになっていた。前の週には別のチームが、会話履歴の生のデータを検索して並べ替えるだけの構成が、7つの評価設定のうち6つで1位になったと報告している（arXiv・2026-10-22）。独立した2本の研究が、同じ方向を示したことになる。

なぜ起きるか メモリは「覚えておくべきこと」を整理して保存するが、その段階で、後から必要になる細部が落ちる。前の週の研究は、生の情報を残しておくことが効いていると分析している。整理された記憶は読みやすいが、質問が想定から外れたときに、根拠へさかのぼれなくなる。

クライアントとの会話での使い方 「長期記憶つきのエージェント」を勧められているクライアントには、まず素朴な RAG のベースラインを作って比べるよう勧めたい。メモリ製品を評価するときは、「何を覚えるか」だけでなく「何を捨てているか」を聞く。※筆者見解：記憶の機能は差別化の宣伝文句になりやすいが、2本の論文は、仕組みを足すことが常に得になるわけではないと示している。

今週の Takeaway

  1. 開発者の端末と依存パッケージを「AI ツールのサプライチェーン」として管理する。LiteLLM と Claude Code 拡張の件が2週続いた。
  2. モデルの選定は用途ごとに分け、ライセンスと価格の条件まで比べる。Terra・Carbon・Large 4 は、得意な用途も提供の条件も違う。
  3. メモリやハーネスのような上乗せの仕組みは、素朴なベースラインと比べてから入れる。メモリ税の論文と TraceTrial-Bench が根拠になる。
