技術動向

Kimi K3.1 Pro のウェイト公開：商用の線引きはライセンスごとに違う

ソース: Hugging Face・2026-11-04

前号で触れた Kimi K3.1 Pro のウェイト公開の続報。Moonshot は予告どおり 11/4 に、総パラメータ2.8T（アクティブ104B）の MoE モデルのウェイトを公開した。文脈は約1M トークン。ライセンスは独自のもので、直近12カ月の売上が2,000万ドルを超える事業者が、API などで第三者に推論やファインチューニングを提供する場合は、Moonshot との別契約が要る。月間利用者1億超か月商2,000万ドル超の商用製品には、UI に名称を表示する義務がある。第三者に提供しない社内利用は、どちらの条件も対象外だ。

クライアントには「社内で使う分にはほぼ制約がないが、自社 SaaS から推論 API を外に出す構成は別契約の対象になりうる」と説明できる。前号の Mistral Large 4 と同じく、オープンウェイトでも商用の条件はライセンスごとに違う。ベンチマークは自社公表だ。米国の公共部門向けなど、中国製モデルを避ける要件がある案件では、性能以前に対象外になる。

GPT-6 Cyber：脆弱性の「発見」が速まると「修正」が追いつかない

ソース: OpenAI・2026-11-05

OpenAI は、脆弱性の発見と修正に特化した GPT-6 Cyber を発表した。提供はサイバー防御向けのプログラム Daybreak の最上位、Daybreak Red に限り、本人確認がある。前日の記事では、自律的な仕組みで Linux カーネルのローカル権限昇格の脆弱性948件を見つけ、検証し、パッチ案まで作ったとしている（要確認。報道では「potential issues」とされ、確定した件数かは分からない）。

クライアントには、脆弱性の発見がモデルで大量に進むと、パッチを当てる運用部門の処理が追いつかなくなる、と説明したい。脆弱性管理の体制と SLA を見直す材料になる。前号の Gemini 4 Carbon と同じく、高いサイバー能力は申請制で配る形が揃ってきた。

Claude Code：エージェントの端末から、想定外の経路で情報が出る

ソース: GitHub Issue・2026-11-05 / Apiiro・2026-11-05

Claude Code の 2.1.318（macOS）で、Web 検索の際にアカウントのメールアドレスが User-Agent に入り、外部のサイトに送られていたと報告された。同日、Anthropic 側の担当者は、これを防ぐ仕組みを既定で有効にしたと回答した。別件で Apiiro は、「Yes, and don’t ask again」で承認したコマンドが文字列のまま設定ファイルに保存され、パスワードや API キーを含んだまま公開リポジトリに上がっている例を報告した。報道では、実際の秘密情報を含む公開コピーは1,122件とも1,379件ともされる（要確認）。

クライアントには、コーディングエージェントは従来の開発ツールより情報が外に出る経路が多い、と説明できる。エージェントの設定ファイルを .gitignore とシークレットスキャンの対象に入れ、承認したコマンドに秘密情報がないかを点検する項目を、導入ガイドラインに加えるよう勧めたい。

ビジネス活用

Anthropic が S-1 を修正：伸びは鈍化、計算資源の確約は約9,000億ドル

ソース: SEC EDGAR・2026-11-02・Anthropic・業界: AI ベンダー

前号で触れた S-1 の続報。Anthropic は 11/2 に修正版（S-1/A）を提出した。CNBC によると、2026年第3四半期の売上は約170億ドルで、前期比の伸びは約47%と、第2四半期の144%、第1四半期の132%から鈍った。第3四半期の純損失は232.9億ドル。購入契約とリースによる支払いの確約は合計約8,954億ドルで、ほぼすべてが計算資源とインフラ向けだという。TechCrunch によると、値下げで売上の伸びが約6億ドル減ったとの記載もある。数字はいずれも二次報道によるもので、要確認だ。

伸びは続いているが鈍り、計算資源の確約は積み上がった。※筆者見解：上場後は収益の圧力が価格や提供条件に響く可能性がある。クライアントの契約更新では、価格改定と提供条件の変更に関する条項を確かめるよう勧めたい。前号で触れた上位顧客への集中度は、今回読めた報道には出ていない。

クレディセゾン：全社員に配ったら、月半ばでクレジットが枯渇

ソース: ITmedia ビジネスオンライン・2026-11-04・クレディセゾン・業界: 金融（クレジットカード）

クレディセゾンは2025年9月1日、国内の全社員約3,600人に ChatGPT Enterprise を配った。毎月初めに150万クレジットへ戻る枠を、2026年6月15日に使い切り、インスタントモード以外が使えなくなった。小野和俊 CDO 兼 CTO は「さすがにトークン枯渇は起こらないだろうと高を括っていた」と話す。同社は「白黒とカラーで値段が違うコピー機」に例え、普段はインスタントモード、深い推論や画像生成は必要な場面だけ、と各部門の会議で周知し、月内の利用を続けられるようにした。月1回以上の利用者は91.7%（2026年3月）だった。

席数ではなくクレジットで課金されるプランを提案するときの注意点として引ける。技術的な制限ではなく、使い方の周知で乗り切った点も参考になる。同じ週、ChatGPT と Codex が同じ利用枠を使うようになると報じられた（TechCrunch・2026-11-02）。※筆者見解：利用枠の見積もりは、今後さらに重要になる。なお、同社の約230万時間の業務削減は、2019年からの DX 全体の累計と読める（※筆者見解）。AI 単独の効果と混同しないよう注意したい。

三井住友ファイナンス＆リース：顧客別の改修を Replit で、6人・半年が1人・1週間に

ソース: ITmedia AI+・2026-11-06・三井住友ファイナンス＆リース・業界: リース（SaaS）

三井住友ファイナンス＆リース（SMFL）は、200社超と有償契約している資産管理クラウド「assetforce」に、Replit のバイブコーディングの機能を組み込み、顧客ごとのカスタマイズを自然言語で作れるようにする。両者をつなぐ開発基盤「ADP」で認証と権限を確かめ、企業が許可したデータと操作だけを通す。品質管理のエージェントが決定論的なテストでコードを検証し、最後は SMFL のエンジニアが確認してから実装する。assetforce の改修では、6人・約半年と見込んだ開発が1人・1週間で終わったという。

「顧客ごとのカスタマイズは高い」というパッケージ SaaS の前提を変える例だ。権限の関所、自動テスト、人の最終確認の3段で品質を担保する設計は、SIer やパッケージベンダー向けの提案の型になる。200画面超のシステムで開発・テストの期間が3分の1になるという数字は、見込み値である点を添えたい。

規制・ガバナンス

Anthropic は開発の加速をリスクとして開示、日本はエージェントの監視が手薄

ソース: SEC EDGAR・2026-11-02 / ITmedia エンタープライズ・2026-11-06・管轄: US / JP

Anthropic は S-1/A に、責任あるスケーリング方針（RSP）が定める「AI に起因する劇的に加速した進歩」の基準に、将来のモデルが近づく可能性があると追記した（TechCrunch・2026-11-02）。現在のモデルが基準を超えたとは認めていない。主要ベンダーが自社の開発の速さを投資家向けのリスクとして開示したことは、ベンダー評価に「安全方針の運用と開示」を入れる根拠になる。

国内では KnowBe4 の調査で、日本のセキュリティリーダー75人のうち79%が AI エージェントを導入済み（世界平均58%）で、導入組織の34%が人の監視が限られたまま自律稼働させていた（同17%）。回答数は少なく、調査主体は管理製品を出すベンダーでもある。エージェントの導入提案には、利用状況の可視化と監視の体制をセットで入れたい。

連載: 事例深掘り「freee、月100万枚の帳票処理を自社 SLM に」

ソース: ITmedia エンタープライズ・2026-11-07・freee・業界: 会計 SaaS

freee は、freee 会計などの AI OCR で月100万枚の帳票を処理している。2つある工程の一方を、8B クラスのオープンウェイトモデルを LoRA で調整した自社の小型モデル（SLM）に置き換えた。同社の資料では、「Claude Sonnet 4.6」相当のモデルと比べ、テキスト項目の精度は最大10ポイント上がり、速度は5倍、コストは50分の1になった。6月の AWS Summit Japan 2026 での木佐森慶一氏の講演の記事（会員限定）から、判断の筋道を追う。

1. なぜ置き換えたか 外部 API は従量課金で、処理量に比例して費用が膨らむ。木佐森氏は「向き合うべきは、現実的なコストで月100万枚をさばくというビジネス上の課題です」と話す。

2. 何を絞ったか 画像からの文字起こしと、テキストから日付・金額・取引先などを抜き出す工程のうち、置き換えたのは後者だけだ。学習に使った正解データは約1万枚、検証とテストには数万枚を使った。※筆者見解：全工程を一度に替えず、範囲を絞ったことが成否を分けたとみられる。

3. どこでつまずいたか 最初は自社でホストしても、外部 API 並みの速度しか出なかった。AWS のチームと1日がかりで推論の設定を見直し、スループットの不足を乗り越えた。

4. 判断の物差し 同社は「Claude Haiku 4.5 で安定して解けるタスクなら 8B の SLM に置き換えられる」という目安を示す。試作の段階でスループットを実測すれば、コストは逆算できるという。本番後も評価・監視・改善を回し続ける。

提案に使うときの注意 コスト50分の1は、従量課金と、GPU を時間で借りる時間課金の違いから来ている。安定した大量のトラフィックが前提だ。※筆者見解：処理量が少ない業務や、波の大きい業務では同じ効果は出にくい。数値は freee の講演資料にもとづき、第三者の検証はなく、比較したモデルも6月時点のものだ。

今週の Takeaway

  1. AI の利用枠とコストは、展開の前に見積もる。クレディセゾンのクレジット枯渇と freee の自社 SLM は、使い方の周知と処理の置き換えという別々の抑え方を示した。
  2. コーディングエージェントの設定ファイルと端末を、情報管理の対象に入れる。Claude Code のメールアドレス送信と、承認ルール経由の秘密情報の公開が同じ週に報告された。
  3. オープンウェイトの採用では、性能より先にライセンスの商用条件を確かめる。Kimi K3.1 Pro は、外部への API 提供に別契約を求める。
